# Harness Engineering 技能指南

## 概述

Harness Engineering技能指导AI代理将现有代码库演进为更易于AI理解和维护的形式。该方法专注于在不重写项目的前提下，通过渐进式改进增强代码库的可见性、可预测性和可维护性。

## 何时使用此技能

此技能应在以下情况下使用：

1. 审计实时代码库以符合Harness Engineering原则
2. 强化AGENTS.md和项目文档
3. 添加可执行的治理和CI检查
4. 逐步减少隐藏上下文和架构漂移
5. 将关键知识移至本地化工件
6. 添加可预测的项目结构

## 工作流程

### 阶段1：代码库审计 (代码库审计)

1. **项目结构分析**
   - 分析项目根目录和关键文件
   - 识别现有的文档和工件
   - 理解技术栈和架构

2. **依赖关系映射**
   - 识别外部和内部依赖
   - 分析构建和部署流程
   - 理解开发工作流程

3. **现有文档评估**
   - 评估README.md、AGENTS.md、CONTRIBUTING.md等文档
   - 识别知识缺口和过时信息
   - 评估文档的可发现性和可访问性

### 阶段2：核心知识库创建 (知识库构建)

1. **标准文档结构创建**
   - 创建/更新AGENTS.md作为主要入口点
   - 建立docs/目录结构
   - 创建核心文档：ARCHITECTURE.md、core-beliefs.md、quality-score.md

2. **知识工件化**
   - 将关键知识从隐藏上下文移至显式文档
   - 创建可搜索的参考文档
   - 建立文档维护工作流程

3. **项目结构标准化**
   - 建立一致的目录结构
   - 创建配置文件模板
   - 标准化命名约定

### 阶段3：可执行治理设置 (治理实施)

1. **质量检查配置**
   - 配置静态代码分析工具（Checkstyle、PMD、SonarQube等）
   - 设置代码格式化工具
   - 配置依赖安全扫描

2. **CI/CD流水线增强**
   - 添加自动化测试和质量门
   - 配置部署检查
   - 建立发布验证流程

3. **监控和可观测性**
   - 添加日志记录标准
   - 配置指标收集
   - 建立性能监控

### 阶段4：渐进式改进规划 (改进规划)

1. **技术债务识别**
   - 创建技术债务追踪器
   - 优先级排序改进项
   - 制定渐进式改进计划

2. **架构一致性检查**
   - 识别架构漂移
   - 建立架构决策记录
   - 创建架构治理检查

3. **团队协作优化**
   - 建立代码审查流程
   - 创建贡献指南
   - 设置知识共享机制

### 阶段5：验证和完成 (验证交付)

1. **完整性验证**
   - 运行质量检查脚本
   - 验证文档链接和引用
   - 测试自动化工作流程

2. **交接文档创建**
   - 创建项目维护指南
   - 记录决策和权衡
   - 提供进一步改进建议

## 可执行检查

### 质量检查脚本

为每个项目类型创建适当的检查脚本：
- **Java项目**：Maven/Checkstyle/PMD集成
- **JavaScript项目**：ESLint/Prettier/单元测试
- **Python项目**：Pylint/Black/单元测试
- **通用项目**：依赖检查、许可证合规、安全扫描

### 标准配置文件

包括标准配置文件模板：
- **代码格式化配置**（.editorconfig, prettierrc, .pylintrc等）
- **静态分析配置**（checkstyle.xml, pmd-ruleset.xml, .eslintrc等）
- **构建配置**（pom.xml更新，package.json脚本，requirements.txt）

## 渐进式改进原则

### 关键原则

1. **不重写原则**：避免大规模重写，专注于增量改进
2. **文档优先**：先记录再重构，保持上下文完整性
3. **自动化优先**：将手动流程转换为自动化检查
4. **渐进式采用**：分阶段实施改进，最小化中断
5. **团队协作**：设计易于团队采用的变更

### 避免的陷阱

1. 避免创建过多的一次性脚本
2. 避免引入不必要的复杂性
3. 避免破坏现有工作流程
4. 避免过度文档化
5. 避免忽视团队反馈

## 技术栈特定指南

### Java/Spring Boot项目
- 添加Maven质量插件
- 配置Checkstyle和PMD规则
- 添加JaCoCo代码覆盖率
- 创建Spring Boot特定文档模板

### JavaScript/React项目
- 配置ESLint和Prettier
- 添加单元测试框架
- 创建组件文档标准
- 设置构建优化检查

### Python/Django项目
- 配置Pylint和Black
- 添加类型提示检查
- 创建API文档标准
- 设置依赖管理检查

### 通用Web项目
- 添加浏览器兼容性检查
- 配置性能预算
- 创建无障碍访问标准
- 设置安全头检查

## 成功标准

### 短期成功指标
1. 所有核心文档创建完成
2. 基本质量检查脚本运行成功
3. 项目结构标准化
4. 技术债务识别和优先级排序

### 中期成功指标
1. 自动化检查集成到CI/CD
2. 文档保持最新且可访问
3. 团队采用新工作流程
4. 架构一致性改进

### 长期成功指标
1. 代码质量指标持续改进
2. 新成员上手时间缩短
3. 技术债务逐渐减少
4. 项目可持续性增强

## 维护和演进

### 持续改进循环
1. **季度审计**：每季度审查和更新文档
2. **工具更新**：定期更新静态分析工具
3. **流程优化**：基于团队反馈优化工作流程
4. **知识刷新**：保持文档与代码同步

### 扩展可能性
1. **自定义检查**：根据项目需求添加自定义检查
2. **集成扩展**：与现有工具链集成
3. **团队培训**：创建团队采用指南
4. **指标仪表板**：建立质量指标可视化
