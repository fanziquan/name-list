# Harness Engineering 通用指南

## 核心原则

### 1. 通用性原则
- 技能文档应适用于任何项目类型
- 避免引用特定项目、团队或组织的名称
- 使用通用的术语和描述
- 提供可定制的模板而不是硬编码的内容

### 2. 可配置性原则
- 使用占位符（如`[项目名称]`、`[数据库类型]`）代替具体值
- 提供配置选项而不是预设值
- 支持多种技术栈和架构风格
- 允许用户根据项目需求进行调整

### 3. 渐进式改进原则
- 分阶段实施改进，不要求一次性完成所有工作
- 提供不同复杂度的实施路径
- 允许团队根据自身情况选择适合的改进速度
- 保持向后兼容性

## 避免项目专属规则的指导

### 应避免的内容
1. **特定项目引用**
   - ❌ "Name-List项目的数据库配置..."
   - ✅ "项目的数据库配置应包含以下要素..."

2. **团队特定规则**
   - ❌ "我们团队的代码审查流程..."
   - ✅ "建议的代码审查流程包括以下步骤..."

3. **组织特定要求**
   - ❌ "根据公司安全政策..."
   - ✅ "常见的安全最佳实践包括..."

4. **特定技术栈假设**
   - ❌ "对于Spring Boot项目..."
   - ✅ "对于Java后端项目，考虑以下配置..."

### 通用化策略

#### 模板化
```markdown
# [项目名称] 架构设计
## [技术栈] 配置指南
```

#### 条件性指导
```markdown
如果项目使用[技术A]，则考虑[方案A]。
如果项目使用[技术B]，则考虑[方案B]。
```

#### 可配置选项
```markdown
配置选项：
- 数据库类型：[MySQL/PostgreSQL/MongoDB]
- 缓存方案：[Redis/Memcached/本地缓存]
- 部署环境：[Docker/Kubernetes/传统部署]
```

## 技能使用模式

### 标准工作流程
1. **发现阶段**：了解项目现状和技术栈
2. **定制阶段**：根据项目特点选择适用的模板和指导
3. **实施阶段**：应用选定的改进措施
4. **验证阶段**：检查实施效果并提供进一步建议

### 适配不同项目类型

#### Web应用项目
- 关注前后端分离架构
- 提供API设计指导
- 包含性能优化建议
- 考虑安全性要求

#### 微服务项目
- 关注服务间通信
- 提供服务发现和配置管理指导
- 包含监控和日志聚合建议
- 考虑部署和扩展性

#### 库/框架项目
- 关注API设计稳定性
- 提供版本管理指导
- 包含文档生成建议
- 考虑向后兼容性

## 质量检查标准

### 文档质量
- [ ] 无特定项目引用
- [ ] 使用通用术语
- [ ] 提供可配置选项
- [ ] 包含多种技术栈指导
- [ ] 分阶段实施建议

### 模板质量
- [ ] 使用占位符而非具体值
- [ ] 支持多种配置选项
- [ ] 提供示例和说明
- [ ] 保持简洁和可读性

### 脚本质量
- [ ] 支持跨平台运行
- [ ] 提供错误处理和日志
- [ ] 包含配置选项
- [ ] 提供详细的使用说明

## 扩展和定制

### 添加新模板
1. 识别常见的项目模式
2. 创建通用模板
3. 提供配置选项
4. 添加使用示例

### 更新现有内容
1. 定期审查通用性
2. 更新技术栈支持
3. 添加新的最佳实践
4. 移除过时的指导

### 社区贡献
1. 鼓励用户贡献模板
2. 建立评审流程
3. 维护质量标准
4. 提供贡献指南
